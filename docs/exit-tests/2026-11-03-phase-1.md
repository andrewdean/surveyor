# Phase 1 exit test: cold index, per-commit update, and Cairn without an adapter

The RFD's Phase 1 exit test reads: a full index of Causeway `main` cold in under ten
minutes and under thirty seconds per typical commit; and a second, unrelated
repository (Cairn) indexes with no adapter and answers `explain` and `affected`
correctly. This document records the run on 2026-11-03.

**Result: passed.** Causeway indexes cold in 3.5 to 9.4 s. Replaying its last twenty
commits through `surveyor update` cost 0.9 to 4.6 s per incremental step (median
1.0 s) on the name tier and 1.1 to 3.2 s (median 1.1 s) with every SCIP index loaded;
the two commits that changed a package manifest fell back to a full index as
designed, at 5.4 s and 4.0 s, and were the slowest steps. Cairn,
with no profile and no adapter, answered eleven of twelve questions correctly at depth
1 on the name tier alone and refused the twelfth honestly; with a `rust-analyzer`
index it answered all twelve. All 247 spans the Cairn answers cite exist
and contain the text claimed. The run found six defects in Surveyor, four of them
in the paths an adopter of `surveyor update` and the precise tier walks every day,
and all six are fixed, in commit `f1f021f` and in the commit that carries this
document, which the numbers above are from. A seventh, in the identities of
overloaded Rhai functions, is recorded and left open.

The exit test as the RFD wrote it does not exercise everything Table 7 lists for
Phase 1. The last section says what is not built.

## 1. Cold index of Causeway

Budget: ten minutes. Measured: the eight cold runs today took between 3.5 and 9.4 s,
with and without indexes and with the machine variously loaded, for 4,366 files into 60,965 nodes. Without indexes the graph has
258,611 edges and 22,593 unresolved references; with the 62 indexes, 239,766 edges of
which 130,322 are `resolved`, and 6,686 unresolved references. Peak memory 1.4 GB.
The budget is met by two orders of magnitude, so I did not profile further.

Three things the table shows. First, a typical commit costs about a second, of which
the fixed part (loading the stored graph, hashing the tree, the Lance delete and
append) is most. Second, the relink count, not the commit size, is what moves the
time: commit 1008 touched two files but relinked 220, because one of them declares
names that many files use, and commit 997 touched 32 files and relinked 273; both
still finished under three seconds. Third, the two commits that changed a package
manifest (994 and 999, which edited `Cargo.toml` files) fell back to a full index, as
the design says they should, and at four to six seconds that fallback costs less than
the budget allows for an incremental step.

Loading the indexes adds about a tenth of a second to each update. After the twentieth step the name-tier dataset holds 258,794 edges and 22,593 unresolved references, and the indexed one 239,867 and 6,686; section 4 compares both with a cold index of the same tree.

The replay also measured something the design assumed rather than tested: what the
precise tier is worth between index refreshes. The indexes were built at the last
commit, so for the first nineteen steps they described a future tree. A cold index of
`main~20` with those indexes still resolved most of the graph (7,977 unresolved against
6,686 at the commit the indexes match), because a declaration that did not move pairs
regardless, and each step converged toward the matching count as files took the shape
the indexes describe. That is the behavior section 17's recommendation relies on: an
index produced on the default branch at the adopter's cadence serves every commit
between refreshes.

## 4. Defects found

Six fixed today, in commit `f1f021f` and in the commit that carries this document,
which the measurements are from, and one left open. Two came from the Cairn answers, four from the replay,
and the four from the replay are in the paths an adopter of the precise tier and of
`surveyor update` walks every day. The Phase 0 numbering continues.

**D6. `explain` listed an impl's methods under a type the impl only mentions.** The
member list took every `Impl` node with a `USES_TYPE` edge to the type, so `impl
From<&RunnableReport> for RunnableValidationSummary` contributed `from` to
`RunnableReport`. An impl's name is its self type followed by `#impl`, and the
member list now keeps only impls written for the type. The fixture gained a
`DrainSummary` with exactly this impl, and the CLI test asserts both sides.

**D7. Lookup was case-insensitive at the top rank.** `explain Dimension` was refused
as ambiguous between the enum `Dimension` and the module `dimension`. An exact-case
match now outranks one that differs only in case, so `Dimension` is the enum,
`dimension` the module, and `DIMENSION` is still ambiguous between them. Qualified
queries that match only the simple name still report "not found" with the candidates.

**D8. A SCIP index built in another checkout matched nothing, silently.** An index
records the absolute path of the project it was built from. The replay clone sat at
another path, so all 65 indexes re-rooted outside the repository and the first replay
with indexes measured exactly the name tier: identical node, edge and gap counts, and
only a `WARN` line under `--verbose` to say so. This is the case the RFD recommends
as the default, an index produced by CI on the default branch and loaded in a
developer's clone, so it had to work. The loader now finds the shortest suffix of the
index's project path, or the repository root itself, at which one of the index's
documents exists under this repository, re-roots there, and logs it; an index none
of whose documents exist here is reported and skipped. In the clone, 62 of the 65
indexes re-rooted this way and the three that did not are `scip-python` indexes with
no documents.

**D9. `surveyor update` re-extracted changed files without the indexes.** The
incremental path built its extractors from the profile alone, so every file a commit
touched lost its precise facts and kept only name matching, while the engine stamp
still counted the indexes. Over the first corrected replay the unresolved count grew
from 7,977 to 12,036 across twenty commits, against 6,686 for a cold index of the same
final tree. The update now builds the same extractors a full index does, once per run,
and re-extracts with them. A unit test re-extracts a path with and without an index
written from another root and checks that the `scip` facts are present only with it.

**D10. A relinked file could not see the declarations of files that did not change,
wherever the linker looks them up by file.** This is the one that mattered. The
linker seeds a relink with the surviving nodes and edges, and the symbol index they
feed is how a relinked file resolves names against the whole repository. Four lookups
go by file rather than by name, and those were built from the fact sets of the run,
which in a relink are the relinked files alone: the declaration at a file and line
that a precise binding names; the symbol inside a module that `import { x } from
"./b"` binds; the members of a class or module a receiver narrows a call to; and the
`DEFINES` and `IMPLEMENTS` edges that pair a trait's methods with an implementation's.
So a relinked implementation lost its `DISPATCHES_TO` edges when its trait was
untouched, a relinked TypeScript file lost the symbol half of its imports, a relinked
call on an imported receiver fell back to fan-out, and a relinked file's precise
bindings failed to pair unless their targets were relinked too. On the name tier
the replay ended with the same 22,593 gaps as a cold index but 438 fewer edges (292
`DISPATCHES_TO`, 119 `IMPORTS`, 27 `CALLS`) and 33 fan-out calls a cold index resolves
to one target; with indexes, 251 more gaps. The Phase 1 equality check of 2026-10-31
had passed because none of its four synthetic edits crossed such a boundary. The
seed's declarations now enter the per-file lookups, and its `DEFINES` and
`IMPLEMENTS` edges feed dispatch. The update harness gained three scenarios, a trait
file relinked alone, an implementation relinked alone and an importer relinked alone,
each checked for node, edge and gap equality with a fresh index; the second failed
before the fix. After the fix the name-tier replay ends with exactly a cold index's 258,794 edges and 22,593 gaps, and the indexed replay with exactly its 6,686 gaps. The edge sets differ in two places: 27 calls inside `cluster.rhai` whose overloaded functions swap their `#2` identifiers between a cold run and a relink (D12, open); and, with indexes, 163 calls the replay drew by name where a cold index draws one precise edge, and 62 the other way, 0.04% of the graph, in files relinked while the index built at the last commit still described a declaration that had not moved into place, which the next refresh heals.

**D11. A gap stayed a gap when the declaration it names moved.** With a precise
index built at the last commit and loaded at `main~20`, a binding that names a
declaration at the line it will have later fails to pair until the declaring file
takes that shape; when it does, nothing relinked the referencing file, because the
planner's rules looked at declarations whose content hash changed or whose name's
declaration set changed, and a moved declaration is neither. The planner gained a
fifth rule: a file with an unresolved reference naming a declaration in a changed
file is relinked. Its cost is bounded by the number of gaps, and it is tested on a
qualifier mismatch whose target moves without changing.

**D12, fixed 2026-11-04. Overloaded Rhai functions swap identifiers between runs.**
Two `fn resolve_otel` of different arity in `cluster.rhai` are `resolve_otel` and
`resolve_otel#2`, numbered in the order the linker met them, and the Rhai AST lists
functions in no particular order; a cold index and a relink of the file met them in
different orders, so 27 call edges attached to the other twin. The edge set was the
same and nothing was lost, but an identifier an agent cited could name the other
overload after an update. The linker now numbers a file's declarations by their
position in the file, whatever order the extractor emitted them in; the test links
the same two overloads in both orders. `LINK_REVISION` moved to 15.

**And one more.** A Rust `use pkg::module::symbol` resolved to the package node and
the symbol, and the import edge shared its confidence between them (0.5). A package,
the module file and the symbol imported from it are one binding; confidence is now
shared only among targets of the same kind. `LINK_REVISION` moved to 14, so a
dataset an earlier build updated incrementally is rebuilt in full on its next update.

## 5. What Phase 1 did not deliver

Table 7's "delivers" column for Phase 1 names more than the exit test measures. Two
items are not built, and this document should not be read as saying they are.

The **Causeway adapter** does not exist; Causeway is indexed through a profile in
Surveyor's `examples/` directory. Of the five contributions section 7.3 assigns it,
two landed in the core instead because they turned out to be general: functions a
Rust host exposes to Rhai, and design documents cited from code. The schema-naming
rule for component migrations, the outbox relay as an explicit node, and the catalog
join remain, and open question 3 (licensing) decides which repository they live in.
The **extractor rows** of Table 4 that Causeway uses and Surveyor lacks are protobuf,
OpenAPI, the Kubernetes and Compose YAML workloads, Dockerfiles and Cedar policies;
nothing in the exit test's questions needed them, and the operations personas of Phase
4 are their first consumer.

The exit test as written passes, and the phase closes on it. The adapter and the
extractor rows carry forward, and the next step the RFD names after this test is open
question 7: removing graphicle from Causeway.
